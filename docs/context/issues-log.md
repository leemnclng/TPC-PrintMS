## Resolved Issues

| 2026-09-01 | Backend | Desktop startup repeatedly reported `Backend has not started yet` and could spend unnecessary time invoking `uv` and rechecking legacy/config files. | The IPC bridge now retains the real readiness promise and failure, Windows launches the existing virtual-environment Python directly, config mirroring runs after readiness, and legacy file migration is marked complete after its first pass. |
| 2026-08-31 | Settings | Environment changes could exceed the 15-second backend readiness timeout, and Windows could reject backup publication or transiently lock restore folders. | Stage switches now receive 120 seconds and fail immediately on an early backend exit. Backup uses a flushed hash-verified copy fallback, restore retries unique folder swaps, and successful recovery reloads the full renderer state. |
| 2026-08-31 | Printing | Photo Print showed job paper dimensions but could not submit an owner-entered custom output size for one attempt. | Photo setup now validates custom short/long edges, updates the proof, and persists driver geometry while preserving the approved material for pricing and stock deduction. |
| 2026-08-31 | Printing | Photo Print rejected a 4×6 borderless job even though the same Canon queue printed it through Canon PRINT. | Removed the unreliable public `PrintableArea` capability gate. Borderless now requests zero margins, renders against physical page bounds, and lets the installed driver finalize or clip the output. |
| 2026-08-31 | Job Orders | The multi-product transaction modal analyzed printing files but no longer showed the document preview, and required inputs were difficult to distinguish from optional fields. | Each analyzed printing line now embeds the continuous PDF/image viewer with explicit fallback states. Required inputs and the required analysis action receive a persistent label plus a highlighted pending state until completed. |
| 2026-08-30 | Products | Product removal either deleted immediately or left referenced records visible as Inactive, with no recovery window. | Deletion now hides every product immediately, offers service-level Undo for five days, and then finalizes automatically. Unused rows are purged; referenced rows retain only a hidden non-restorable audit identity. |
| 2026-08-30 | Pricing | Workflow-level global tables did not make the product dimension visible, and the Pricing Center spread a small amount of pricing data across an oversized ledger. | Configuration now exposes the existing product-rate layer through the same material × print-type matrix, while Pricing Center uses compact base matrices and service-grouped product rows. Materials sharing a paper size remain separate rows. |
| 2026-08-30 | Job Orders | Production-line cards displayed status and facts but did not clearly expose how to continue each product's workflow. | Each pane now opens a contextual process area through whole-card pointer interaction or a visible keyboard-accessible step toggle. Mutating operations remain explicit actions, with state-specific guidance and locked-record behavior. |
| 2026-08-30 | Scanning | Automatic scanning used the flatbed while the original was in the feeder, B&W could stop before acquisition, and trigger outcomes were easy to miss. | The bridge now selects WIA 2.0 source items instead of always transferring item 1, treats a reported feeder-ready bit as authoritative, and uses feeder-first automatic fallback. Owners can override the source. Unreliable B&W and grayscale acquisition were later retired in favor of the validated Colored path; scanner checks/acquisitions retain persistent progress, success, cancellation, and error guidance. |
| 2026-08-30 | Workflow | Service-first intake could create only one operation and disabled Custom services because no single category-wide workflow was defined. | Transactions now use each selected product's stored operation. The initial service scopes the first line only; later products may come from any service, including Custom, while preserving independent production and one combined payment/completion. |
| 2026-08-30 | Scanning | Starting a scan opened a redundant Windows WIA configuration dialog outside the job workflow. | Printing-MS owns the fixed Colored content intent plus DPI and capture-size settings and skips `ShowSelectItems`. It uses only WIA's transfer/progress path to activate drivers that do not respond to direct item transfer. |
| 2026-08-30 | Scanning | Direct WIA item transfer did not activate the Canon scanner, while the scan action remained available without a document. | Acquisition now uses `CommonDialog.ShowTransfer` without the redundant settings selector. Feeder paper is accepted when WIA reports it; flatbed or non-sensing drivers require explicit placement confirmation, enforced again by the desktop IPC boundary. |
| 2026-08-30 | Scanning | Newly acquired WIA pages appeared as broken images, and job intake forced the owner to choose a scanner source. | The Windows bridge converts driver-native output to validated PNG and retains automatic source selection. Placement confirmation appears only when the driver cannot reliably report a loaded original. |
| 2026-08-29 | Scanning | Scanner failures exposed raw PowerShell/COM errors and scanning could start without a placement preflight. | The desktop bridge discovers WIA devices first, returns structured recovery errors, blocks jams/open covers, and requires either detected feeder paper or explicit placement confirmation. |
| 2026-08-29 | Scanning | Scan job creation required a scanner output to be attached manually and asked the owner to re-enter its page count. | Printing-MS now launches the installed Windows WIA scanner UI, receives and previews each acquired page, derives the page count, combines multiple captures, and retains the resulting softcopy. Manual import is recovery-only. |
| 2026-08-29 | Scanning | Printing-MS reported no Windows scanner while Canon PRINT could scan from the connected device. | The Canon app and Windows WIA use different discovery paths. Installing the model-specific Canon IJPAT driver/package registered the scanner with WIA and restored Printing-MS discovery. The Windows installation guide now records this prerequisite and validation flow. |
