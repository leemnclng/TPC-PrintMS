# App Context

This folder tracks product and engineering context for the app over time.

Use these files as living notes when features are added, issues are found, or implementation decisions change.

## Files

- [progress-log.md](progress-log.md): chronological updates about completed work and active progress.
- [change-log.md](change-log.md): notable app changes grouped by date.
- [issues-log.md](issues-log.md): known bugs, risks, blockers, and follow-up items.
- [functionality-map.md](functionality-map.md): current app features and expected behavior.
- [decisions.md](decisions.md): product and technical decisions with rationale.
- [build-plan.md](build-plan.md): phased plan for the initial Windows and macOS desktop application.
- [initial-pages.md](initial-pages.md): initial navigation, page contents, workspaces, and functionality coverage.
- [ux-development-standard.md](ux-development-standard.md): required interaction patterns, UI states, accessibility, and completion checklist for user-facing features.

## Update Habit

When making a meaningful app change:

1. Add a short entry to `progress-log.md`.
2. Record user-facing changes in `change-log.md`.
3. Update `functionality-map.md` if behavior changed.
4. Add unresolved problems to `issues-log.md`.
5. Capture important tradeoffs in `decisions.md`.
